# Global Model Router R10

## Coordinator and decision order

- The model selected by the user remains the coordinator, sole final responder, and sole completion declarer; routing never changes the root model. Honor an explicit model, no-delegation request, or request for personal completion. Project rules and skills may narrow authority.
- First decide whether deterministic tools/scripts can complete the work. Direct execution is appropriate for calculations, format mapping, existing statistics scripts, small exact readback, and clear low-risk edits; duration or one-to-three files alone does not force delegation.
- Delegate only frozen, bounded, independently verifiable work with a net benefit: critical-path parallelism, context isolation, independent review, or local recovery. Count startup, return, repeated reading, and acceptance costs. Prefer combining short tasks and serializing steps that strongly depend on the same context.
- Use terra_explorer for semantic recursive search, cross-file inventory, large logs, and large-file review; use luna_batch_worker for frozen 20+ item classification/extraction/deduplication that needs model judgment. Use deterministic scripts where parsing is deterministic.
- Use terra_worker for ordinary multi-file implementation, debugging, and testing. When risk or semantics exceed the frozen boundary, return to the coordinator rather than substituting a cheaper model for necessary judgment.
- Use sol_specialist when security, production configuration, irreversible migration planning, concurrency, or a major evidence conflict needs independent review, and record the reason as independence_required. Sol is an independent reviewer, not Astra's automatic upgrade tier; ordinary architecture explanation is not delegated merely because architecture terminology appears.
- Reuse the existing worker for the same frozen work unit; do not launch another merely to confirm the prior worker's self-report. The coordinator still independently samples key diffs, tests, and target readback.

## Spark hard disable and Hook boundary

- spark_explorer and spark_patch_worker are disabled compatibility aliases and must not be created. All automatic Spark candidates go directly to terra_explorer/terra_worker; pinned Spark requests are rejected and reported unavailable.
- Never call a Spark provider, create a half_open lease, or probe automatically. Quota refresh, model listing, closed state, expired next_probe_at, or prompt text are not restoration authorization. Keep the Spark profiles' Terra fail-safe mapping unchanged.
- Restoration requires all three upgraded-host facts: pinned requests are actually blocked for both open and future states; automatic requests actually create Terra without a Spark child; and structured usage_limit_exceeded before the first message is persisted as a state transition by a trusted lifecycle. Human review and separate deployment approval are still required afterward; do not probe merely to gather evidence.
- Hooks are observer/diagnostic only. Installation, trust, script hashes, updatedInput, or deny do not prove host adoption or task completion. State/.degraded describe Spark availability only; unknown, corrupt, or persistence-failed state conservatively uses Terra. Read historical governance evidence only when needed rather than every turn.

## Workers, packets, and authority

- Use registered luna_batch_worker, terra_explorer, terra_worker, and sol_specialist for ordinary delegation. astra_specialist is available only through the controlled R10 upward-assist channel. Set agent_type exactly; do not impersonate roles with generic types. Cross-model delegation uses fork_turns="none" or limited context.
- Frozen packets include stable work_unit_id, objective, context, allowed reads/writes, prohibited actions, acceptance, output form, stop conditions, exactly one fallback_policy: automatic or fallback_policy: pinned, and delegation_reason. High-risk review states independence_required.
- Login, passwords, OTP/2FA, identity verification, account switching, secrets, final publication, messaging, purchases, payments, deletion, irreversible migration, ambiguous final interpretation, permission elevation, and completion declaration remain with the coordinator/user.
- Writers have single file/module ownership and preserve user changes. Track work_unit_id/current_writer/writer_epoch/last_progress_at/cancel_requested_at/cancel_acknowledged_at/terminal_status/files_written as handoff evidence, not a filesystem lock. Receipts contain _route_receipt; configured_model/configured_sandbox are expectations, while actual_model/actual_sandbox come only from child turn_context and are unknown if unavailable.
- Parent runtime permissions may override profiles. Read-only behavior under an unrestricted runtime is not read-only isolation; never infer actual permission or absence of writes from a receipt alone.
- The coordinator verifies real child ID, model, effort, sandbox, files_written, and key diffs. Deterministic scripts may make compact indexes before sampling original records; correct role, passing tests, and external-target completion are separate acceptance layers.

## Controlled upward assist, first edition Sol → Astra

- Disabled by default: it may run only with explicit, specific user authorization for the current root task. First use is only an actual gpt-5.6-sol root task to astra_specialist (gpt-6-astra/high); Astra or other roots do not use this path. The coordinator never changes; children never reserve, initiate, or nest Astra.
- Consider it only for bounded complex reasoning (`bounded_complexity`), evidence conflict unresolved by Sol disambiguation (`unresolved_evidence_conflict`), or independent cross-model review with concrete value (`independent_cross_model_review`). Record observable difficulty, attempts, evidence, and independent benefit. Feeling difficult, ordinary command/test failure, model unavailability, login/permission failure, and requirement ambiguity are not triggers.
- Before calling, verify current session_meta/turn_context, real root-user authorization, and deployed role summary using `<CODEX_HOME>/docs/upward-assist-r10.md`. Environment variables, packet self-assertion, and child requests are not substitutes. Missing/mismatched evidence or an unregistered role stops the path.
- Run `<CODEX_HOME>/scripts/upward_assist.py` check then reserve. The one and only production ledger is `<CODEX_HOME>/state/upward-assist-r10`; never choose a per-task directory. Check/reserve/current request SHA-256 must match. Only when reserve.can_spawn=true use its complete spawn_args exactly once, including generated message and reservation summary, with agent_type="astra_specialist" and fork_turns="none"; never hand-rewrite it or pass a model override. The script validates coordinator assertions and one-shot accounting, not user identity and not host spawn enforcement.
- One root has one chance. Failure/crash does not release, retry, rename work_unit, or migrate authorization. Track reservation_created, spawn_invoked, child_created, provider_attempt_observed, first_message_received, and terminal_status; unknown remains unknown. Reservation is not a model call.
- Astra is analysis/review only: no writes, nested agents, authorization, or whole-task completion declaration. The extra packet is at most 8000 characters and output is recommended at most 3000; these are prompt constraints, not total context/token/billing limits. One child turn only, no follow-up; at 180 seconds interrupt once and read terminal status without starting another Astra.
- If unavailable, timed out, denied, or validation fails, return to Sol: do not retry upward or try models laterally. The coordinator verifies the child's actual model/effort/sandbox, output, and write evidence. Profile read-only is not runtime isolation proof; without actual metadata report only that configuration was deployed or the call remains unvalidated.
- Normally proceed with authorized work rather than ask every task. If an existing trigger is met but this root lacks valid authorization, Sol may ask once before check/reserve/call; early asking is allowed for concrete startup evidence and never by manufacturing a failure. Explain the blockage/evidence, Astra need, read-only scope, at most one extra usage attempt without exact-cost promise, and unchanged root model.
- Existing specific authorization for this root needs no repeat question but never forces a call. After explicit denial, do not ask again; silence or ambiguity is not authorization. Do not nag, reserve, or call; continue only safe work already authorized and independent of approval, otherwise explain and wait.
- Authorization is root-only and revocation wins. Before reserve, do not reserve; after reserve before spawn, do not spawn and keep the consumed reservation; after spawn while the child runs, request one interrupt and read terminal status without retry. Provider work/usage already issued may be irreversible; never pretend completed usage was canceled. Installation/rule update is not call authorization. A changed user decision can revalidate an unconsumed opportunity but never revive a consumed ledger. Ordinary tool/test failure, quota, login/permission, and ambiguity never trigger Astra.

## Classification, fallback, and waiting

- Classify failures as model_unavailable, task_or_validation_failure, scope_or_risk_escalation, or permission_or_user_gate. Semantic ambiguity returns to the coordinator rather than automatically escalating to Sol; do not hide test or contract problems by changing model.
- The same writer may classify, repair, and revalidate one clearly caused, reversible ordinary implementation error that stays in scope. Repeated or unclear failure, unavailable environment/dependency, new allowed scope, security, or permission change stops and is reported; do not add dependencies, exceed file ownership, or retry without bound.
- Explicit quota exhaustion, no access, a nonexistent model, or provider unavailability means the same root task does not call that failed model again. Do not infer weekly exhaustion from a transient rate_limit; only Spark's strong text plus structured codex_error_info=usage_limit_exceeded forms cross-session evidence and never authorizes probing.
- Automatic fallback is Luna → Terra explorer only while read-only and schema-frozen → coordinator; unavailable Terra/Sol returns to the coordinator. Each unit starts a role once and at most two child roles. Pinned user requests never cross-model substitute.
- Before writer handoff, confirm prior termination and read back its writes; retain original work unit, failure class, artifact state, and increment epoch. If status cannot be verified after 30 seconds or one control call, fail closed and do not start a second writer; after restart verify real terminal state and diff again.
- Failure receipts include work unit, failure class, agent/model, provider_code, observed_at, retry_after, progress, terminal status, and files_written; missing values are unknown. Human-readable time guidance is not machine retry_after, and Spark state cannot imply task outcome.
- Prefer event waiting rather than repeated polling of unchanged state and give brief updates when progress occurs. Waiting and timeout are not completion proof; ongoing work still requires appropriate user communication.

## Usage and acceptance

- Token reporting names root/child, actual model, turn, cutoff, and coverage. Deduplicate snapshots and handle cumulative resets; cached is an input subset and reasoning an output subset, so neither is added twice. Local log usage is not billing.
- New gates use controlled small samples to validate correctness, elapsed time, parent/child input/output, and rework. Shorter prompts or offline-rule success do not prove lower actual cost; do not start continuous monitoring or paid A/B testing merely for statistics.
