# 多 Agent 协作合同

## 核心原则

多 Agent 的沟通单位是可检查工件，不是聊天共识。每个 Agent 返回来源、文件、测试、截图、回执、差异或失败说明；意见只能解释工件，不能替代工件。

## 每个步骤必须定义

- 稳定步骤 ID；
- 执行者；
- 依赖步骤；
- 允许读取和允许写入的对象；
- 输出对象；
- 入口和出口门禁；
- 可产生的 Claim；
- 副作用、幂等性和恢复计划。

临时任务路径不是永久角色。根据当前瓶颈创建有边界的步骤，任务结束后释放。

## 工位模型与运行核验

- 当前用户规则和部署 profile 是任务路由的规范来源；读取、执行、复杂分析和独立复核分开选工位。能解析的分类、计数、字段比较先用脚本，不让模型代替确定性验收。
- 记录 `requested_model/effort`、宿主当前的 `registered_model/effort`、profile 的 `configured_model/sandbox` 与 child `turn_context` 的 `actual_model/effort/sandbox`。这四层可以不一致，配置和请求都不能代替运行证据。
- 固定角色可能忽略 model 或 effort 覆盖参数。仅当工位已注册且注册映射符合本次目标时调用；首次以只读校验取得真实 child ID 和元数据，映射不符则停止该路径，由原协调者接管，不换通用角色或反复覆盖参数。
- 没有已注册的对应低成本工位时，保持已有角色的任务和写入合同；只读批处理角色不能成为普通执行或可写工位的替身。配置已落盘、宿主已加载、实际调用匹配分别记录。
- 模型不可用的后备与任务验收失败分开处理。后备工位也必须已注册且模型匹配；写入交接先确认前者终态、读回工件，再递增 writer_epoch。模型映射不符不等于账户无访问权。
- 子工位返回的 `matches_expected`、`pass` 或字段缺失只作为待核对结果。对可解析原文重新计算关键断言；例如所有字段正确但汇总布尔值错误时，保留反证，由脚本结果决定相应字段验收。

需要核验一次模型路由时，使用 [validate_agent_route.py](../scripts/validate_agent_route.py)，显式传入单个 profile、单个 child transcript、父子 ID、请求模型、请求 effort 和当前注册模型。多回合 child 必须指定 turn ID。脚本按真实元数据比较模型与 effort，不执行模型、修改配置或证明宿主强制隔离；实际 sandbox 与配置分开报告。

## 共享对象

跨文章、封面、DOCX、发布记录或代码分支时，不按文件前缀、列表顺序或“第几个”关联。为每个逻辑对象建立稳定 ID，并维护：

- 当前源文件和输出工件；
- 内容或文件哈希；
- 所有者和写入策略；
- 当前 Claim 与证据；
- 被替代版本。

`single_writer` 对象只能由一个步骤写。多写者对象必须是 `append_only`，或声明 `merge_required`、合并步骤与合并负责人。

## 协调者

唯一用户侧协调者负责：

- 任务主合同与架构选择；
- 子任务边界和集成顺序；
- 冲突裁决；
- 用户更新与授权确认；
- 最终完成声明；
- 端到端验收。

全合同只能有一个 `completion_writer`。子 Agent 的“完成”只表示它的边界内有候选工件或检查结果；不自动提升整个任务状态。

## 交接

每次交接至少新增一项：

- 工件引用；
- 证据引用；
- 决策引用；
- 状态变化引用。

只有“我完成了”“我同意”或聊天摘要的交接无效。

## 冲突与集成

- 并行只用于低耦合、可独立验收的分支。
- 共享核心对象指定唯一写入者，其他 Agent 只读、提议补丁或串行进入。
- 事实冲突回到来源和证据优先级。
- 体验、隐私、商业风险和对外承诺进入人工门禁。
- 集成后重新运行相关自动检查和端到端人工验收。

## 审核容量

开始并行前写明质量、耗时、成本、工具调用、人审时间和恢复时间的基线与预算。人工审核容量小于并行产出时，减少并发、缩小输出或改为串行；不要把待审积压误写成效率提升。

## 多体升级

进入 `approved`、`tested` 或 `adopted` 前，必须满足：

- 单体基线已完成，或因强制职责隔离获人工批准豁免；
- 保存了稳定失败与瓶颈；
- 使用同一任务集摘要和输入快照；
- 写出可证伪假设、指标、方向和最小改善阈值；
- 保存单体与多体运行引用；
- 记录协调、合并、验证和重试的额外成本。

只记录“多 Agent 更好”视为无效升级理由。
